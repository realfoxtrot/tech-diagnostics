## D. Вордмарк AS-RUSSIA — оценка вариантов

Требование владельца: «начертание AS-RUSSIA должно совпадать с логотипом ASUS».
Логотип ASUS — проприетарный кастомный шрифт (визуально близок к Eurostile / Microgramma Bold Extended).
Бесплатного точного соответствия не существует.

**Ранжирование (мой вердикт):**

**1 место — (d) плейсхолдер за CSS-переменной + лицензированный шрифт позже. ЭТО НАДО ОТГРУЖАТЬ.**
Уже частично сделано: `--font-brand` в `globals.css`, утилита `font-brand` в `SiteHeader`/`SiteFooter`,
имя шрифта нигде не захардкожено. Замена — один файл в `public/fonts/` + одна строка в `layout.tsx`.
Юридически чисто, технически обратимо, стоимость смены — минуты.
Оговорка: сейчас плейсхолдер — **Michroma** (Google Fonts, OFL). Michroma — не Eurostile:
у него другая буква `S`, круглые `O`/`U` и заметно другая ширина. Совпадение «на глаз» слабое.
Рекомендую как целевую замену купить **Eurostile Bold Extended (Linotype) / Microgramma Bold Extended (URW)** —
это тот самый класс шрифта, от которого отталкивался ASUS. Веб-лицензия — порядка $50–150 за начертание.

**2 место — (b) похожий бесплатный шрифт как окончательное решение.**
То же, что (d), но без пути к точному совпадению. Приемлемо только если владелец
откажется покупать лицензию. Из тройки Michroma / Orbitron / Zen Dots ближе всего Michroma,
но ни один не «совпадает».

**3 место — (a) отрисовать бренд картинкой из официального `n-logo-asus.svg`.**
Это официальный товарный знак ASUS. Использовать его как **собственный** логотип
партнёрской компании — прямое нарушение прав на товарный знак, даже для авторизованного сервиса.
Отдельно: файл на CDN ASUS может измениться/исчезнуть, хотлинк недопустим.
Годится ровно одно применение — маленькая плашка «Авторизованный сервисный партнёр ASUS»
рядом с нашим логотипом, по правилам бренд-гайда и с письменного разрешения.

**4 место (не отгружать) — (c) перекроить официальный SVG в «AS-RUSSIA».**
Официальных форм существует только для A, S, U (из `ASUS`). Для `R`, `I` и дефиса
официальных начертаний нет — их придётся рисовать самостоятельно. Результат —
**не «совпадение с начертанием ASUS», а подделка**: смесь подлинных глифов товарного знака
с самодельными. Хуже, чем честный похожий шрифт, по двум причинам сразу:
юридически это производная работа от товарного знака, а визуально гибрид всё равно палится
на нарисованных буквах. Плюс это неподдерживаемый артефакт — любое изменение текста требует иллюстратора.

**Что отгружать:** вариант (d). Сегодня — плейсхолдер (Michroma или иной extended-гротеск),
`--font-brand` уже изолирует решение. Параллельно — запрос владельцу продукта на бюджет
лицензии Eurostile/Microgramma Bold Extended, после покупки — замена одного `.ttf`/`.woff2`.
Пока лицензии нет, честнее написать заказчику «точного совпадения нет и без лицензии не будет»,
чем выдать вариант (c) за совпадение.

### D1. [major] Плейсхолдер-шрифт выдаётся за решение, критерий приёмки не задан
Ни в одной спеке нет строки «вордмарк». Правка попала в `app/layout.tsx` вне мандата (B3),

- `#4a9bd4` на `#16273d` (accent-soft тёмной темы) = 4.98:1 — на грани, для мелкого 13px рискованно.
- белый 75% (`#c8d8e6`) на `--hero-from #23659b` = 4.23:1 — **ниже 4.5:1** для строки фактов 14px.
Фикс: в `.dark` ввести отдельный `--accent-on` (текст на акценте) = `#0b1220`, для белого на акценте
использовать более тёмный `--accent: #1f6fb2`; строку фактов в hero поднять с 75% до 85% непрозрачности
или градиент начинать с `#1d5a8c`.

### E4. [major] Клавиатурная доступность и фокус-стили не проверяются
Есть `focus:ring-accent` на инпутах `SupportWrapper`, но у ссылок-плиток, CTA, бургер-меню и
`<details>` FAQ фокус-стиль не задан — при `focus:outline-none` где-либо фокус пропадёт полностью.
Мобильное меню не закрывается по Escape, фокус не возвращается на кнопку.
Фикс: глобальный `:focus-visible` outline в `globals.css`; прогон Tab по `/` и `/support`.

### E5. [blocker] Нет rate limiting на `POST /api/support/request`
Публичный неаутентифицированный эндпоинт пишет строку в SQLite без каких-либо ограничений.
Тривиальный флуд: цикл curl → неограниченный рост `data/diagnostics.db` и мусор в поддержке.
Где: `app/api/support/request/route.ts`.
Фикс: in-memory лимит по IP (например 5 запросов / 10 минут) + honeypot-поле в форме.
Спека P2 требование не содержала вовсе.

### E6. [major] Отсутствуют ограничения длины полей — DoS по объёму
`lib/support.ts` `validateSupportInput` проверяет максимум только у `fullName` (≤200).
`description`, `city`, `phone`, `email` верхней границы **не имеют** — можно записать мегабайты.
`phone` и `city` не валидируются по формату вообще.
Фикс: `description` ≤ 5000, `email` ≤ 254, `phone` ≤ 32 (+ regex), `city` ≤ 100.

### E7. [major] Персональные данные: 152-ФЗ не отработан
Новая таблица `support_requests` хранит ФИО, email, телефон, город, серийный номер — это ПДн.
Отсутствует: страница политики конфиденциальности (grep по `политик|privacy` — 0 совпадений),
чекбокс согласия ссылается в никуда, нет срока хранения/удаления, нет ограничения доступа
(таблица не выводится в админке, но и не защищена отдельно), БД лежит нешифрованной в `data/`.
Фикс: страница `/privacy`, ссылка из чекбокса, ретенция (например автоудаление через 180 дней),
вкладка в админке под `isAdmin()`, права `600` на файл БД.

### E8. [major] Коллизия пространства номеров TD- между двумя таблицами
`makeTicketNumber()` в `lib/support.ts` генерирует `TD-YYYYMMDD-XXXX` в том же формате, что и
`app/api/ticket/route.ts` для таблицы `sessions`. Уникальность проверяется **только внутри
`support_requests`**. Итог: один и тот же номер может существовать в обеих таблицах, а
`/ticket?ticket=TD-...` ищет только в `sessions` → пользователь с номером обращения в поддержку
получит «Обращение не найдено».
Фикс: отдельный префикс для поддержки, например `SR-YYYYMMDD-XXXX`, либо проверка уникальности
по обеим таблицам.

### E9. [minor] XSS/инъекции — риск низкий, но не нулевой
`messageText` попадает в `<textarea value=…>` — React экранирует, DOM XSS нет.
Drizzle параметризует SQL — инъекции нет. Остаётся: CRLF-инъекция в `description`
портит структуру текста обращения, и `console.error` логирует объект ошибки с данными пользователя.
Фикс: нормализовать переводы строк, не писать содержимое запроса в логи.

### E10. [major] Сквозной сценарий поддержки не тестируется
P2 требует только 3 curl-проверки API. Не проверяется: рендер результата, работа кнопки копирования
(`navigator.clipboard` требует secure context — на `http://` в проде **не сработает**, останется
только `document.execCommand` fallback, который deprecated), открытие ссылки ASUS, поведение при
двойном сабмите, состояние после ошибки сети.
Фикс: ручной сквозной прогон в браузере + явная проверка, что прод отдаётся по HTTPS.

### E11. [major] Регресс существующего функционала не проверяется
P1 перекрашивает `WarrantyChecker`, `DiagnosisChat`, `CentersMap`, `AdminPanel`, `LoginForm` —
5 интерактивных компонентов. `tests/` содержит только `diagnosis.test.ts` и `warranty.test.ts`
(логика, не UI). Пины карты MapLibre раньше были `#4f46e5`/`#818cf8` — цвет менялся строкой в JS;
после замены на токены надо убедиться, что пины вообще рендерятся.
Фикс: ручной прогон: проверка гарантийности до результата, полный диалог диагностики до тикета,
карта СЦ с кликом по пину, вход в админку и CRUD.

### E12. [minor] `npm run lint` — «warnings допустимы, если были и до»
Формулировка непроверяема: базовый уровень предупреждений нигде не зафиксирован.
Фикс: сохранить `npm run lint` до правок в файл и сравнивать.

### E13. [minor] Нет проверки, что тёмная тема переживает редизайн
P1 §«Токены» требует «тёмная тема ДОЛЖНА остаться рабочей», но ни одна из проверок её не включает —
все curl-запросы отдают светлую тему (класс `.dark` ставится клиентским скриптом).
Фикс: ручной прогон всех страниц с `localStorage.theme='dark'`.

### E14. [minor] Нет проверки SSR/гидратации
`SupportWrapper` использует `useEffect(() => setMounted(true))` с подавленным правилом ESLint
`react-hooks/set-state-in-effect` — обход линтера вместо решения. Гидратационных предупреждений
никто не проверяет (в curl их не видно, только в консоли браузера).
Фикс: открыть страницы в браузере и убедиться в чистой консоли.

### E15. [minor] `robots.txt` / `sitemap.xml` отсутствуют
Новая публичная страница `/support` не индексируется осмысленно. Вне требования, но
для «готового сайта» стоит добавить.
