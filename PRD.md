# Программа диагностики и ремонта вычислительной техники

## Проблема
Пользователь с неисправным ноутбуком не знает: что случилось, можно ли починить самому (программно), и куда нести, если нет.

## MVP-цель (этап 1)
Без регистрации: диалоговая диагностика → траблшутинг программных причин → если не помогло — техдокумент истории + направление в сервисный центр из списка.
 

## Пользовательский поток
1. Пользователь заходит на сайт (без регистрации) → попадает в диалог.
2. Алгоритм задаёт вопросы, ветвится по ответам → уточняет тип проблемы.
3. Траблшутинг: рекомендации + доп. вопросы → попытка устранить программную причину / ошибку пользователя. 
Рекомендации выдаются так же, как и вопросы, — по одной: в конце каждого шага задаётся вопрос с вариантами ответов о результате его выполнения. Если проблема не решена и в цепочке траблшутинга есть дальнейшие шаги — взаимодействие продолжается, иначе переходим к пункту 4.
4. Если не получилось → создаётся история диагностики (техдокумент), выдаётся:
   - номер обращения + штрих-код (по нему доступна карта диагностики)
   - список сервисных центров. Список СЦ должен содержать географическую карту (на основе yandex карт)содержащую кликабельные пины всех доступных в нашей базе сервисных центров (по клику на пине переход на карточку СЦ под картой) и под картой карточки с адресами и контактами СЦ.
   /Users/mac3/dev/tech-diagnostics/data/documents/Список Сервисных центров.xlsx
      
5. Пользователь выбирает СЦ → обращение привязывается к нему.

## Функции бэкенда (админка)
- Редактирование дерева вопросов диагностики (CRUD).
- Редактирование рекомендаций/решений для программных причин (CRUD).
- Редактирование списка СЦ: контакты, адреса, координаты (CRUD).

## Этап 2 - лендинг ✅

- Создание лендинга сервисной компании AS-RUSSIA с логотипом в виде передней части белого единорога вылетающего на нас из звездного неба. Лендинг должен убеждать пользователей, что компания является самой авторитетной структурой по устранению неисправностей ноутбуков (обширная сеть сервисных центров, самая экспертная служба технической поддержки, самый обширный доступ к запасным частям). На видном месте должны быть основные средства навигации для перехода на проверку гарантийности (-пока создай страницу заглушку), переход на оформление запроса в службу технической поддержки (тоже пока заглушка), поиск и устранение проблем (траблшутинг), список авторизованных сервисных центров. 

## Этап 2.1 - проверка гарантийности

Страница /warranty (ранее /garranty; старый адрес редиректит 308), механика повторяет as-russia.ru:
- Форма: «Дата покупки» + «Серийный номер» + кнопка (Enter тоже шлёт), спиннер во время запроса.
- AJAX POST /api/warranty/check → {errors, messages, serial_number}; ошибки красным, сообщения — под блоком «Результат проверки:»; при вводе нового значения результат очищается.
- Валидация: SN 12–20 символов (буквы/цифры/дефис), дата покупки не в будущем.
- Предварительный расчёт: гарантия 24 мес. с даты покупки («действует до …» / «истёк …»); финальный статус по данным поставщика уточняет техподдержка.
- Обращения хранятся в warranty_checks; админка → вкладка «Гарантийность» — список со статусами, legacy-записи можно подтвердить вручную.
- Интеграция вендора: POST https://as-russia.ru/api/check_sn (Auth: Bearer). Вендор проверяет ТОЛЬКО: валидность SN (ноутбук ли), страну отгрузки, дату отгрузки. Вердикт «подпадает/не подпадает» выносит локальная логика — вендор не считает гарантию. Токен в файле `data/vendor_token.txt` (вне git, права 600; переменная `WARRANTY_VENDOR_TOKEN_FILE`), меняется раз в 1–2 года.
- Условия централизованной гарантии ASUS (4 пункта, показаны на странице и в чеклисте результата): 1) тип продукта — только ноутбуки; 2) регион продаж — Россия; 3) дата продажи по чеку с 01.01.2026 (проверяется локально); 4) дата производства по SN не ранее 01.07.2025 (по данным вендора).
- Результат проверки: чеклист 4 условий с иконками ✓/✗/… (pass/fail/unknown) + причины отказа текстом.
- Статусы проверки: `covered` (только messages от вендора), `rejected` (локальный отказ или errors вендора), `error` (вендор недоступен).

## Вне MVP (позже)
- Монетизация: централизованная оплата ремонта/комплектующих, service fee СЦ.
- Централизованная сеть поставки запчастей на основе статистики диагностики и ремонтов.
- Расширение на десктопы, планшеты, смартфоны.

## Ключевые требования
- Пользователь без регистрации (нет аккаунтов).
- Диагностика воспроизводима: всё, что спрошено и отвечено, сохраняется в историю.
- История доступна по номеру обращения / штрих-коду (публичная ссылка).
- Админка защищена (пароль, env-переменная).
